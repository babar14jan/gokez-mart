           customerId; it resolves the customer from auth or the OTP-verified
           session link
    [DONE] mart_carts.order_id, so every conversion reconciles against a real
           order (ON DELETE SET NULL withdraws it if the order is deleted)
    [DONE] the funnel counts a conversion only when its order still exists
    [OPEN] customer session identity does not expire
    [OPEN] guest orders are not linked to a session/channel
    [OPEN] campaign touch window and coverage are incomplete
    [OPEN] login_abandoned is recorded but absent from EVENT_STAGE_DEFS, so it
           is never displayed
    [OPEN] product_viewed is deduplicated per session, not per product

  Migrations 054-057 are still untracked and unapplied anywhere. The earlier
  full-chain re-apply test fails at 001_initial_schema.sql, which is NOT
  re-runnable (it uses ON CONFLICT on a constraint added by a later migration).
  That is pre-existing and unrelated: the supported path is one ordered pass from
  zero, which applies all 55 cleanly. 055 and 057 re-apply cleanly on their own.

  31 pre-existing date formatters omit the timeZone option and rely on the
  machine's local zone. Out of scope for the IST work - new code passes the
  zone explicitly.

  SettingsService.updateMany() updates keys one query at a time, so a multi-key
  save is not atomic. A partial failure leaves some keys written.

  Campaign supersede/audit backlog is a separate workstream, untouched.
